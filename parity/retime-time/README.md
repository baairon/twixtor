# retime-time parity module

Measures the time model and frame choice of the `retime` rewrite (`vectors=1`, No Vectors) against
`Twixtor_64.aex` under the emulator. Scope: `time_remap_mode`, `speed_percent`, `frame_num`,
`in_fps_is_out_fps`, `input_frame_rate`, `src_mark_segments`, `input_fields`, `frame_interp`, at 8, 16
and 32 bpc. Every case sets `vectors=1`. Graded against the original: the result is `results/summary.json`, and [docs/parity.md](../../docs/parity.md#status) shows it with the other modules.

The bar: same inputs, identical outputs (bytes at 8 and 16 bpc, bits at 32 bpc, `--max-ulp 0`).

## Files

| File | Does |
|---|---|
| `gen_grid.py` | Writes the test set (`cases.json`, `grid.json`, `out_of_contract.json`, `not_graded.json`, `inputs/`). Own PRNG, no ffmpeg, deterministic. |
| `not_graded.json` | The four cases left out of the grid, with the reason ([Test set without the Bezier handle cases](#test-set-without-the-bezier-handle-cases)). |
| `render_grid.py` | Renders every case with one `vfx` binary and records exit, size and SHA-256 per case (`--check-only` runs `--check`). |
| `check_oob.py` | Runs the out-of-contract candidates through `--check` and a render. |
| `mutants.py` | The mutant table and the patcher (scratch copy only). |
| `analyze.py` | Compares mutant renders with the base render; writes `results/summary.json` from the result files. |
| `stage1.sh`, `mutants_run.sh` | The server drivers of phase A. |
| `results/` | Small result files: `base.tsv`, `mut/*.tsv`, `mutants_vs_base.{json,tsv}`, `out_of_contract.tsv`, `check_all.tsv`, hashes, `summary.json`. |

`grid.json` gives every case a group and a class. Class `value`: constant parameters, graded
directly. Class `logic_parity`: keyed curves, where the host interpolates keyframes; the emulator
side needs a labelled stand-in, the same one the rewrite uses.

## Re-run (server, `$WORK/retime-time/`)

```sh
tar --force-local -cf - analyze.py check_oob.py gen_grid.py mutants.py mutants_run.sh render_grid.py stage1.sh \
  | ssh -o BatchMode=yes compute 'mkdir -p $WORK/retime-time && tar xf - -C $WORK/retime-time && bash $WORK/retime-time/stage1.sh'
# mutants (builds, about ten minutes): run as a job
python ~/.claude/skills/ionos/scripts/ionos.py job start tw-retime-time-N --confirm --cwd '$WORK/retime-time' -- 'bash mutants_run.sh'
```

`stage1.sh` copies the base build to `src/`, generates `testset/`, validates it (`--check` of every
case, `fx-parity checklist`, `fx-parity run` with no references), and renders the base grid into
`base-out/` with `results/base.tsv`. `mutants_run.sh` builds each mutant in `mut-src/` (opt-level 1,
no LTO; `m00_control` is the unmutated source built the same way; it should reproduce `base.tsv` apart from NaN payload bits),
renders the grid with each, and writes `results/mutants_vs_base.json`.

`results/cases.json`, `grid.json` and `out_of_contract.json` are copies of the test set's case files (the
frames are regenerated by `gen_grid.py` and never leave the server). `python analyze.py summary --testset results ...`
rewrites `results/summary.json`; `params_used.py` writes `results/params_used.tsv` (the plugin params the grid
relies on, by rewrite param id). A mutant is judged against `m00_control` (same build profile); the control
differs from the base release build only in NaN payload bits of a few 32 bpc cases (`control_vs_base.tsv`).

Phase B (emulator side): render the same `testset/` with the plugin into a refs folder, then
`fx-parity run --testset testset --refs REFS --max-ulp 0`.

## Phase B tooling (`phase_b.py`, `test_phase_b.py`)

Python 3 standard library only; nothing in it runs the plugin. `python3 test_phase_b.py` runs the unit tests (no server needed).
`python3 phase_b.py selftest` runs the stand-in oracles on the server (outputs only under `results/selftest/`).
With real references in `REFS` (one core, from `$WORK/retime-time/`; `FXP=$WORK/harness/repo/target/release`,
an `fx-parity` that knows `--max-ulp`; the module's own `src/` build predates it and predates `VFX_CALL_RECORD`):

```sh
T="taskset -c N python3 phase_b.py"
python3 $WORK/harness/run_harness.py --testset testset --refs REFS -j2 --records RECORDS --summary status.json
$T grade --refs REFS --fx-parity $FXP/fx-parity --vfx $FXP/vfx   # results/grade.json, grade.tsv
$T ooc-set --out ooc-testset                                       # run it through the harness too, add its status file below
$T ooc --status status.json --status ooc-status.json               # results/ooc.json (moves cases out of contract)
$T rewrite-records --vfx $FXP/vfx --out RWREC                       # the rewrite side of the call record
$T calls --plugin-records RECORDS --rewrite-records RWREC           # results/calls.json, calls.tsv
$T kills --refs REFS                                                # results/kills.json (saved mutant tables; --rerender uses mutbin/)
$T summary                                                          # results/summary.json (needs grade.json)
$T triage                                                           # groups differences, writes probe/ (a ladder test set)
```

`grade` counts `no reference` as neither pass nor failure. `ooc` moves a case out of contract when the harness status is `refused`,
`timeout` or an error that starts with `PluginError`; `unsupported`, `not_run` and emulator faults stay in contract as unjudged
(`--ooc-status` changes the set). `kills` uses the definition in `docs/parity.md`: among the in-contract cases where the base rewrite
equals the reference, a mutant is killed iff it differs from the reference (and from the unmutated control build) on one of them.
`summary` never writes `verified` unless the status rule holds for the computed numbers, and never writes `results/verify.json`.


## Test set without the Bezier handle cases

`testset_v2/` (next to `testset/`, which is unchanged) is the grid without four cases that can never get a reference: `keyed-fn-handles` at 8, 16 and 32 bpc (`frame_num=0@0o0/50;11@11i0/50`) and `keyed-sp-handles` at 16 bpc (`speed_percent=100@0o0/50;50@11i-30/50h`). The host computes Bezier key handles and the harness's keyframe stand-in refuses them, so they are not part of the bar; `not_graded.json` lists them with the reason "host-side Bezier interpolation, not part of the bar". The set has 460 in-contract cases (464 before); 46 of them are class `logic_parity` (50 before; the group `keyed` has 26 cases, was 30). Every remaining case has the same id, params, size, source and input file bytes as in `testset/` (the generator still counts the dropped settings when it rotates sizes and sources), and rendered with the module's base `vfx` the 460 cases give the hashes of `results/base.tsv`. Make it with `python3 gen_grid.py testset_v2` and pick it up with `--testset testset_v2` (`run_harness.py`, `phase_b.py`) or `fx-parity run --testset testset_v2 --refs REFS --max-ulp 0`. The phase A result files (`results/summary.json`, `results/base.tsv`, the mutant files) still describe the 464 case grid.
